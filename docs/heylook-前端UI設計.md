# 欸你看（HeyLook）前端與 UI 設計文件

對應後端規劃：[heylook-後端規劃.md](./heylook-後端規劃.md)

---

## 【技術棧】

| 項目 | 選擇 | 說明 |
|------|------|------|
| 框架 | React (Vite) | 開發速度快，社群資源多 |
| 樣式 | Tailwind CSS | 快速堆疊、易於維持一致間距與色階 |
| 路由 | React Router | 依登入狀態保護路由（Protected Route） |
| 狀態管理 | React Context + useReducer（或 Zustand） | 專案規模不大，不需要 Redux |
| API 請求 | Axios（攔截器統一掛 JWT、處理 401） | — |
| 表單 | React Hook Form | 表單驗證（如星級評分、必填欄位） |
| 圖片上傳 | 原生 `<input type="file">` + FormData | 對應後端 multer |
| RWD 策略 | Tailwind 響應式斷點（mobile-first） | 手機／平板／桌面同一套程式碼，非獨立 App |

## 【視覺風格：中性簡約風（Notion 調性）】

### 設計原則
- 白底為主，大量留白，內容density 適中
- 弱化裝飾，用**間距與字重**建立層級，而非色塊與陰影
- 色彩克制：一個主色 + 中性灰階，強調色只用在互動與狀態提示
- 圓角統一、邊框取代陰影來分隔區塊

### 色彩系統

```css
/* 主色：沉穩藍綠（象徵閱讀/沉浸感），非常克制地使用 */
--color-primary:        #2F6F5E;
--color-primary-hover:  #255A4C;
--color-primary-light:  #E8F2EF;   /* 淺底色，如標籤背景 */

/* 中性灰階（介面主體） */
--color-text-primary:   #1F2328;
--color-text-secondary: #6B7280;
--color-text-tertiary:  #9CA3AF;
--color-border:         #E5E7EB;
--color-bg:             #FFFFFF;
--color-bg-subtle:      #F9FAFB;   /* 卡片、次要區塊底色 */

/* 狀態色（僅用於必要提示，不做裝飾） */
--color-success:  #2F8F4E;   /* 儲存成功 */
--color-warning:  #B7791F;   /* 提示性訊息 */
--color-danger:   #C0392B;   /* 下架、刪除 */

/* 星級評分與愛心（僅有的兩處暖色系元素，用於強調） */
--color-star:     #D4A017;
--color-heart:    #D14D4D;   /* 愛心圖示，未按/已按用實心與空心區分，不額外加色階 */
```

### 字型與排版

```css
font-family: -apple-system, "Noto Sans TC", "PingFang TC", sans-serif;

/* 尺寸階層（僅 5 級，避免過度設計） */
--text-xs:   12px;   /* 輔助說明、時間戳 */
--text-sm:   14px;   /* 內文、表單 */
--text-base: 16px;   /* 標準內文 */
--text-lg:   20px;   /* 卡片標題 */
--text-xl:   28px;   /* 頁面標題 */

line-height: 1.6;   /* 中文內容行距需寬鬆 */
```

### 間距與圓角

```css
--radius: 8px;         /* 統一圓角，卡片/按鈕/輸入框一致 */
--spacing-unit: 4px;   /* 8/16/24/32px 為主要間距節奏 */
--border-width: 1px;   /* 用邊框分隔，不用陰影 */
```

## 【頁面地圖】（依登入狀態區分，非角色）

登入後即擁有完整功能，只有「是否登入」與「是否為管理員」兩層區別。

```
公開頁面（訪客可見，無需登入）
├── / 首頁（最新發表心得 + 最新建立作品）
├── /media 媒體庫（列表 + 篩選）
├── /media/:id 媒體詳情（大綱、心得列表、編輯紀錄）
├── /media/:id/history 媒體編輯歷史
├── /users/:id 他人的個人主頁（貢獻總覽：心得／編輯紀錄）
├── /login 登入
├── /signup 註冊（Step 1：填寫資料）
└── /signup/verify 註冊（Step 2：輸入驗證碼）

會員專屬（登入即可用，無額外角色門檻）
├── /media/new 建立媒體資料（強制同時填寫第一篇心得）
├── /media/:id/edit 編輯媒體資料（任何會員皆可，共同維護）

├── /admin 管理儀表板
└── /admin/content 內容管理（下架媒體/心得）
```

## 【核心頁面設計】

### 1. 註冊 `/signup` → `/signup/verify`

註冊是同一個流程的兩個頁面，中間不能跳過。

**Step 1：填寫資料 `/signup`**
```
┌─────────────────────────────────────────────┐
│  註冊                                          │
├─────────────────────────────────────────────┤
│  Email *       [________________]              │
│                                               │
│  密碼 *         [________________]              │
│                                               │
│  暱稱 *         [________________]  ✓ 可以使用   │  ← 即時檢查，debounce 後呼叫
│                                        ✕ 已被使用  │     GET /api/users/check-nickname
│                                               │
│              [取消]  [發送驗證碼]                  │
└─────────────────────────────────────────────┘
```

**Step 2：輸入驗證碼 `/signup/verify`**
```
┌─────────────────────────────────────────────┐
│  驗證你的 Email                                  │
├─────────────────────────────────────────────┤
│  驗證碼已寄至 you@example.com                     │
│  請於 10 分鐘內輸入 6 位數驗證碼                       │
│                                               │
│  [_] [_] [_] [_] [_] [_]   ← 6 格獨立輸入框，自動跳下一格 │
│                                               │
│              [完成註冊]                          │
│                                               │
│  沒收到驗證碼？[重新發送]                             │  ← 呼叫 /api/auth/signup/resend
└─────────────────────────────────────────────┘
```

**互動細節**：
- 暱稱欄位失焦或停止輸入 500ms 後（debounce），呼叫 `GET /api/users/check-nickname?nickname=xxx`，即時顯示可用/已被使用
- Step 1 送出後導向 Step 2，並帶著 email 參數（不用讓使用者重打一次）；若使用者直接用網址列跳到 `/signup/verify` 但沒有先完成 Step 1，導回 `/signup`
- 驗證碼輸入框設計為 6 個獨立方格，輸入一位數字自動跳到下一格，符合常見驗證碼輸入的互動慣例
- 驗證成功後（`POST /api/auth/signup/verify`）後端直接回傳 JWT，前端存好 token 後直接導向首頁，**不需要使用者再手動登入一次**
- 驗證碼錯誤或過期：顯示錯誤訊息，保留輸入框讓使用者重新輸入或點擊「重新發送」

### 2. 登入 `/login`

```
┌─────────────────────────────────────────────┐
│  登入                                          │
├─────────────────────────────────────────────┤
│  Email *       [________________]              │
│                                               │
│  密碼 *         [________________]              │
│                                               │
│              [登入]                             │
│                                               │
│  還沒有帳號？[前往註冊]                              │
└─────────────────────────────────────────────┘
```

**互動細節**：僅 email／密碼兩個欄位，無第三方登入按鈕（Google／Facebook 等）。登入成功後 JWT 存入 localStorage（或 httpOnly cookie，視安全性考量決定），導向首頁。

**登出**：不是獨立頁面，而是導覽列（桌面版頂部／手機版底部「我的」分頁）裡的一個按鈕，點擊後呼叫 `POST /api/auth/logout`、清除本地 token，導向首頁（訪客視角）。

### 3. 首頁 `/`

**設計依據**：新增媒體與發表心得是使用頻率最高的核心行為。首頁拆成「最新發表心得」與「最新建立作品」兩個獨立區塊，各自只顯示少量最新項目（依螢幕寬度決定筆數，非無限捲動）。

**RWD 筆數對照表**：

| 斷點 | 每區塊顯示筆數 |
|------|--------------|
| 手機（< 768px） | 3 筆 |
| 平板（768–1023px） | 4 筆 |
| 桌面（≥ 1024px） | 5 筆 |

兩區塊各自呼叫 `GET /api/reviews/latest?limit=N` 與 `GET /api/media?sort=latest&limit=N`，`N` 依斷點動態決定，不做無限捲動——首頁的定位是「快速瀏覽近況」，看更多則導向對應的完整列表頁（`/media`、心得目前無獨立列表頁，可導向該作品的媒體詳情頁）。

```
┌─────────────────────────────────────────────┐
│ 欸你看                  [媒體庫]  🔔  (頭像)▾ │  ← 登入後：🔔 通知、頭像下拉選單（個人主頁/設定/登出）
├─────────────────────────────────────────────┤
│                                               │
│  最新發表心得                        [查看更多 →]   │
│  ┌─────────────────────────────────────┐      │
│  │ 👤 Bob  ★★★★☆                         │      │
│  │ ┌────┐ 《鬼滅之刃》                        │      │
│  │ │封面 │ 「這集的戰鬥場面畫得太好了...」          │      │
│  │ └────┘                    28 分鐘前         │      │
│  └─────────────────────────────────────┘      │
│  ┌─────────────────────────────────────┐      │
│  │ 👤 Alice  ★★★★★                       │      │
│  │ ┌────┐ 《沙丘：第二部》                     │      │
│  │ │封面 │ 「視覺效果與敘事調度都是頂級水準」       │      │
│  │ └────┘                    2 小時前          │      │
│  └─────────────────────────────────────┘      │
│  ┌─────────────────────────────────────┐      │
│  │ 👤 Cindy  ★★★☆☆                       │      │
│  │ ┌────┐ 《三體》                           │      │
│  │ │封面 │ 「原著粉不能錯過的改編」                │      │
│  │ └────┘                    5 小時前          │      │
│  └─────────────────────────────────────┘      │
│  （手機顯示 3 筆／平板 4 筆／桌面 5 筆）              │
│                                               │
│  ─────────────────────────────────────────    │
│  最新建立作品                        [查看更多 →]   │
│  ┌────┐ ┌────┐ ┌────┐                       │
│  │封面 │ │封面 │ │封面 │                        │  ← 網格卡片
│  │沙丘二│ │三體 │ │鬼滅 │                        │

│  （手機顯示 3 筆／平板 4 筆／桌面 5 筆）              │
└─────────────────────────────────────────────┘
```

**設計重點**：
- 「最新發表心得」與「最新建立作品」是首頁僅有的兩個區塊，各自標題明確、各帶一個「查看更多 →」連結，不強迫使用者滑動載入
- 心得卡片顯示暱稱、星級、心得摘要、對應作品縮圖與時間戳；作品卡片顯示封面、標題、建立者暱稱與時間戳
- 兩區塊資料來源完全獨立（`/api/reviews/latest` 與 `/api/media?sort=latest`），前端不需要合併排序邏輯
- 顯示筆數依斷點縮放（手機 3／平板 4／桌面 5），避免手機版塞入過多卡片造成過度捲動
- 暱稱（Alice / Bob / Cindy）皆可點擊連到 `/users/:id`，作品縮圖可點擊連到 `/media/:id`

### 4. 他人的個人主頁 `/users/:id`

```
┌─────────────────────────────────────────────┐
│  (頭像) Alice                                  │  ← 圓形頭像，未上傳則顯示預設圖示
│  加入時間：2024-06-01                            │
│                                               │
│  最近迷上懸疑推理，歡迎交流書單 📚                     │  ← 自我介紹，未填寫則不顯示這一行
│                                               │
│  貢獻總覽                                        │
│  心得 12　・　編輯過的資料 8                        │
│                                               │
│  [心得] [編輯紀錄]  ← 分頁籤                        │
│  ─────────────────────────────────────────    │
│                                               │
│  （心得分頁）                                     │
│  ★★★★★  《沙丘：第二部》                          │
│  這部片的敘事節奏掌握得很好...            2024-09-01  │
│  ─────────────────────────────────────────    │
│  ★★★☆☆  《鬼滅之刃》                             │
│  劇情稍嫌拖沓，但畫面依然精美            2024-08-20  │
└─────────────────────────────────────────────┘
```

**編輯紀錄分頁內容**（切換分頁籤後，呼應共編模式的貢獻透明化）：
```
│  （編輯紀錄分頁）                                   │
│  《沙丘：第二部》                        3 天前       │
│  修改欄位：synopsis, cover_image_url              │
│  ─────────────────────────────────────────    │
│  《三體》                              1 週前       │
│  修改欄位：release_year                          │
```

**設計重點**：
- 這是小型社交平台的核心頁面之一——認識一位朋友的品味，比看他的自我介紹更重要，因此「貢獻總覽」放在頁面最上方，直接量化這個人在平台上活躍的痕跡
- 兩個分頁籤對應後端兩支 API：`GET /api/users/:id/reviews`、`GET /api/users/:id/media-edits`
- 「編輯紀錄」分頁是差異化擁有權模型的自然延伸：共編媒體資料雖然不是 owner-scoped，但每個人的編輯足跡仍然完整可查，讓貢獻被看見
- 沒有「追蹤」「私訊」等社交互動功能，這一版純粹是「瀏覽與被看見」

### 5. 個人主頁編輯 `/account`

```
┌─────────────────────────────────────────────┐
│  個人主頁設定                                     │
├─────────────────────────────────────────────┤
│  頭像                                          │
│  ┌──────┐                                     │
│  │(頭像)│  [更換頭像]                              │  ← 點擊開啟檔案選擇或拖曳上傳
│  └──────┘                                     │
│                                               │
│  暱稱 *        [Alice____________]  ✓ 可以使用     │  ← 即時檢查，排除自己目前的暱稱
│                                               │
│  自我介紹（選填）                                   │
│  [最近迷上懸疑推理，歡迎交流書單 📚_______]              │  ← 多行文字框，有字數上限提示
│                                          12/200 │
│                                               │
│  Email        you@example.com（不可修改）           │
│                                               │
│              [儲存變更]                          │
│                                               │
│  ─────────────────────────────────────────    │
│  修改密碼                                        │
│                                               │
│  目前密碼 *    [________________]                │
│  新密碼 *      [________________]                │
│                                               │
│              [更新密碼]                          │
└─────────────────────────────────────────────┘
```

**設計重點**：
- 「頭像」「暱稱」「自我介紹」是同一張表單，對應 `PUT /api/users/profile`；「修改密碼」是獨立的表單區塊，對應 `PUT /api/users/password`——兩者是不同的操作意圖，分開送出，避免使用者只想改頭像卻被要求重新輸入密碼欄位
- 暱稱欄位即時檢查邏輯與註冊頁相同（debounce 呼叫 `GET /api/users/check-nickname`），但這裡的檢查需要「排除自己目前使用的暱稱」——如果使用者沒有更改暱稱、只換了頭像或自我介紹，不該被誤判為「暱稱已被使用」（畢竟那就是自己正在使用的暱稱）
- 「更換頭像」點擊後跳出檔案選擇或支援拖曳上傳，選好圖片後在按鈕旁即時顯示預覽，實際上傳發生在按下「儲存變更」的當下（與建立媒體資料的圖片上傳邏輯一致）
- 自我介紹為選填欄位，有字數上限（例如 200 字）並即時顯示已輸入字數；未填寫時，他人個人主頁不顯示這個區塊，不留空白間距
- Email 顯示但不可編輯（帳號的唯一識別，不開放修改，避免衍生二次驗證等複雜度）

### 6. 媒體庫 `/media`

```
┌───────────┬─────────────────────────────────┐
│ 篩選側欄     │  媒體庫              [+ 新增媒體資料]  │  ← 登入後才顯示此按鈕
│           │  ┌────┐ ┌────┐ ┌────┐ ┌────┐     │
│ 類型       │  │📖   │ │🎬   │ │📺   │ │📚   │     │  ← 用小圖示區分類型

│ ☐ 電影     │  │★4.2 │ │★3.8 │ │★4.5 │ │★4.0 │     │  ← 平均星級直接顯示
│ ☐ 影劇     │  └────┘ └────┘ └────┘ └────┘     │
│ ☐ 漫畫     │                                   │
│ ☐ 動畫     │  排序：[最新加入 ▾]                   │
│           │                                   │
│ 格式       │                                   │
│ ☐ 紙本     │                                   │
│ ☐ 電子版   │                                   │
│ ☐ 串流     │                                   │
│ ☐ 院線     │                                   │
└───────────┴─────────────────────────────────┘
```

**互動細節**：
- 類型 icon 對照：📖 書籍／🎬 電影／📺 影劇／📚 漫畫／🎨 動畫
- 卡片右上角小圖示標示 `format`（紙本/電子/串流/院線）
- 篩選為即時查詢（onChange 觸發 API），非送出按鈕
- 「+ 新增媒體資料」對訪客隱藏，登入會員皆可見（無角色門檻）

```
│                                               │
│  大綱介紹                                        │
│  ────────────────────────                      │

│  大家的心得（32）                  [+ 寫下我的心得]     │  ← 登入即可，已寫過則顯示「編輯我的心得」
│  ────────────────────────                      │
│  ★★★★★  Alice                          ♡ 5    │  ← id="review-xxx"錨點；「Alice」可點連到主頁
│  這部片的敘事節奏掌握得很好...                        │  「♡ 5」可點擊按愛心，點數字看是誰按的
│  ────────────────────────                      │
│  ★★★☆☆  Bob                          ♥ 12    │  ← 實心愛心＝我已按過（再點一次取消）
│  中規中矩，但值得一看...                             │
└─────────────────────────────────────────────┘
```

**設計重點**：
- 「編輯資料」按鈕登入即可見，任何會員都能修正媒體基本資訊（共編模式）
- 「最後編輯：小明・3 天前」是共編模式下的關鍵信任機制，讓使用者知道資料的新鮮度與來源；暱稱本身是超連結，點擊可看到這個人的完整貢獻主頁
- 「寫下我的心得」按鈕登入即可見；若已發表過，文案自動變成「編輯我的心得」（呼應後端 unique constraint）
- 心得列表用簡單的分隔線區分，不做卡片化（心得是文字為主的內容，不需要視覺強化）；每則心得的暱稱同樣連到該作者的個人主頁
- 每則心得容器有 `id="review-{reviewId}"` 錨點，供通知點擊後直接捲動定位到該則心得（見下方「我的通知」頁面說明）
- 愛心圖示：空心 ♡ 表示尚未按過（可點擊按讚），實心 ♥ 表示自己已按過（再點一次可取消）；數字是總愛心數，點擊數字開啟「按過的人」清單彈窗
- 自己的心得旁邊不顯示愛心互動圖示（只顯示總數，不可點擊），對應後端「不能對自己的心得按讚」的限制

## 【路由保護的前端實作邏輯】

只有兩層判斷：是否登入、是否為管理員。

```jsx
// ProtectedRoute 概念
function ProtectedRoute({ requireAdmin, children }) {
  const { user } = useAuth();

  if (!user) return <Navigate to="/login" />;
  if (requireAdmin && user.role !== 'admin') {
    return <Navigate to="/unauthorized" />;
  }
  return children;
}

// 路由設定
<Route path="/media/new" element={
  <ProtectedRoute><CreateMediaPage /></ProtectedRoute>
} />

<Route path="/admin/*" element={
  <ProtectedRoute requireAdmin><AdminLayout /></ProtectedRoute>
} />
```

**條件渲染範例**（登入即顯示操作按鈕，不需角色判斷）：
```jsx
{user ? (
  <button onClick={openReviewForm}>
    {myReview ? '編輯我的心得' : '寫下我的心得'}
  </button>
) : (
  <Link to="/login">登入後即可留下心得</Link>
)}
```

**Owner-scoped 前端判斷**（僅心得需要）：
```jsx
{review.user_id === user?.id && (
  <>
    <button onClick={editReview}>編輯</button>
    <button onClick={deleteReview}>刪除</button>
  </>
)}
```

**愛心按鈕的條件渲染**（自己的心得不能按讚，只顯示數字）：
```jsx
{review.user_id === user?.id ? (
  <span>♥ {review.like_count}</span>
) : (
  <LikeButton
    liked={review.liked_by_me}
    count={review.like_count}
    onClick={() => toggleLike(review.id)}
  />
)}
```

## 【響應式設計：Web App，手機／電腦同等支援】

定位是 **Web App**，不是「桌面優先、手機將就」——朋友分享作品這件事，實際發生的場景更常是在手機上（滑到有趣的作品、隨手寫兩句心得）。因此採 **Mobile-first** 開發順序：先做好手機版排版與互動，再擴展到桌面版的多欄佈局。

### 斷點策略

```css
/* Tailwind 預設斷點，維持慣例即可 */
--breakpoint-sm:  640px;   /* 手機橫向／小型平板 */
--breakpoint-md:  768px;   /* 平板 */
--breakpoint-lg:  1024px;  /* 桌面：側欄開始並排顯示 */
--breakpoint-xl:  1280px;  /* 大桌面：內容最大寬度上限 */
```

**核心原則**：
- 預設樣式（無 breakpoint 前綴）即為手機版，`md:` / `lg:` 往上疊加桌面樣式（Tailwind 慣例的 mobile-first 寫法）
- 內容最大寬度設定 `max-width: 1200px`，避免大螢幕上文字/卡片被過度拉伸
- 所有可點擊區域（按鈕、卡片、星級評分）在手機上維持最小 44×44px 觸控熱區

### 版面差異對照表

| 區塊 | 手機（< 768px） | 桌面（≥ 1024px） |
|------|----------------|------------------|
| **頂部導覽** | 精簡 Logo + 漢堡選單，登入按鈕常駐 | 完整文字導覽列（媒體庫／登入） |
| **媒體庫篩選** | 收合為底部抽屜（Drawer），點擊「篩選」按鈕開啟 | 常駐左側欄 |
| **媒體庫列表** | 單欄或雙欄網格卡片 | 四欄網格卡片 |
| **媒體詳情頁** | 封面圖置頂、資訊縱向堆疊 | 封面圖與資訊左右並排 |
| **心得/表單** | 全螢幕頁面（非 Modal），減少手勢誤觸 | 可用置中 Modal 或獨立頁面 |
| **管理員後台** | 側邊欄收合為頂部下拉，表格改為卡片式清單 | 側邊欄常駐 + 傳統表格 |

### 表單與互動的手機優化

- 星級評分元件在手機上放大觸控熱區（星星間距加大，避免誤觸相鄰星等）
- 圖片上傳在手機上優先呼叫裝置相機/相簿（`<input type="file" accept="image/*" capture>`）
- 長表單（建立媒體資料）在手機上以垂直單欄呈現，桌面版可考慮左右分欄加快輸入
- 下拉選單（類型、格式）在手機上使用原生 `<select>`，觸發系統原生選擇器，而非自製下拉元件

### 管理員後台的手機支援

既然定位是全平台 Web App，管理員後台仍需基本手機可用性（例如外出時緊急下架不當內容），但排版可以更簡化：
- 側邊欄選單收合為頂部下拉或漢堡選單
- 表格化資訊改為卡片式清單（每張卡片顯示一筆待處理內容 + 下架按鈕）

## 【與後端規劃的一致性檢查】

| 前端頁面 | 對應後端 API |
|---------|------------|
| 註冊 Step 1（填寫資料） | `POST /api/auth/signup` |
| 註冊 Step 2（輸入驗證碼） | `POST /api/auth/signup/verify`, `POST /api/auth/signup/resend` |
| 登入／登出 | `POST /api/auth/login`, `POST /api/auth/logout` |
| 個人主頁編輯（暱稱、頭像、自我介紹、密碼） | `PUT /api/users/profile`, `PUT /api/users/password` |
| 暱稱即時可用性檢查（註冊＋個人主頁編輯共用） | `GET /api/users/check-nickname` |
| 首頁「最新發表心得」 | `GET /api/reviews/latest?limit=N` |
| 首頁「最新建立作品」 | `GET /api/media?sort=latest&limit=N` |
| 媒體庫、篩選 | `GET /api/media` |
| 媒體詳情（含心得、編輯資訊） | `GET /api/media/:id`, `GET /api/media/:id/reviews` |
| 媒體編輯歷史 | `GET /api/media/:id/history` |
| 建立媒體資料＋第一篇心得（含圖片上傳） | `POST /api/media`（一次請求同時建立兩筆資料） |
| 編輯媒體資料 | `PUT /api/media/:id` |
| 撰寫/編輯既有作品的心得 | `POST /api/media/:id/reviews`, `PUT /api/reviews/:id` |
| 愛心（按讚／取消／查看按讚者） | `POST/DELETE /api/reviews/:id/like`, `GET /api/reviews/:id/likes` |
| 我的通知 | `GET /api/notifications` |
| 他人個人主頁（貢獻總覽） | `GET /api/users/:id` |
| 個人主頁分頁籤（心得／編輯紀錄） | `GET /api/users/:id/reviews`, `GET /api/users/:id/media-edits` |
| 管理員下架 | `/api/admin/*` |

前端頁面地圖與後端路由檔案一一對應，開發時可依此順序：**帳號系統（註冊二階段驗證／登入登出）→ 個人主頁編輯 → 媒體庫瀏覽與共編（含首篇心得） → 編輯歷史 → 心得 → 愛心與通知 → 首頁（最新心得／最新作品區塊）→ 他人個人主頁 → 管理員下架**，與後端 API 開發順序保持同步。

## 【下一階段規劃（暫緩）】

- **邀請制小圈圈**（類似 FB 社團）：新增「建立圈子」「邀請連結／邀請碼分享」「加入圈子」等頁面；圈子首頁彙整該圈子內的最新心得與作品，媒體庫、媒體詳情、通知等既有頁面屆時可能需要加上「目前所在圈子」的篩選範疇，是對現有前端頁面結構影響最大的一項擴充
- **策展主題相關頁面**：`/curated-lists`（全站策展主題列表）、`/curated-lists/:id`（策展主題詳情，收錄作品 + 策展人簡短說明）、`/my/curated-lists`（我的策展主題管理，owner-scoped）；首頁可補回「策展主題精選」區塊，退居次要位置；他人個人主頁的分頁籤也可補回「策展主題」一項
- **podcast、YouTube 等媒體來源**：媒體庫的類型篩選（`/media` 篩選側欄）需新增對應的類型 icon（如 🎙️ podcast／▶️ YouTube）；建立媒體資料表單的「類型」選項需擴充，且這類來源可能需要額外欄位（原始連結、頻道名稱、集數），表單與詳情頁版面需視實際資料結構調整
- `/my/watchlist` 個人待看清單頁面（含 pending/done 狀態切換）
