# 後端開發順序計畫（SDD + TDD）

相關文件：[後端規劃.md](./後端規劃.md)、[資料實體設計.md](./資料實體設計.md)、[API端點設計.md](./API端點設計.md)

## 【開發模式】

本專案後端採用 **SDD（Spec-Driven Development）+ TDD（Test-Driven Development）**：

- **先規格、後測試、後實作**：所有模組的 API 規格（openspec）與對應測試案例，必須在動手寫任何實作程式碼之前全數完成。
- 規格與測試完成後才進入開發，開發順序不必再對照「規劃 → 測試 → 實作」的階段切分，而是純粹依照模組間的依賴關係排列。
- 前後端切分：後端全部完成（含容器化）後才開始前端開發。

---

## 【階段一：規格與測試（全部模組）】

依序為每個模組撰寫 openspec 規格與測試案例（尚未實作）：

1. 帳號系統（auth + users）
2. 個人主頁編輯（users/profile，含頭像上傳）
3. 媒體＋首篇心得建立（media，一次 transaction）
4. 媒體編輯歷史（media_edit_history）
5. 心得系統（reviews，含 /reviews/latest）
6. 愛心與通知（review_likes、notifications）
7. 使用者公開主頁（users/:id）
8. 管理員下架功能（admin）
9. 圖片上傳整合

**驗證**：全部模組的規格文件與測試案例撰寫完成、測試案例可執行（因無實作應全數失敗），才進入階段二。

---

## 【階段二：實作（依模組依賴順序）】

```
1. 帳號系統（auth + users）
   → 驗證：註冊流程正確、登入/登出正常、暱稱唯一性檢查正確

2. 個人主頁編輯（users/profile，含頭像上傳）
   → 驗證：暱稱重複時擋下、允許不改暱稱只改頭像、multer 正確處理頭像檔案

3. 媒體＋首篇心得建立（media，一次 transaction）
   → 驗證：兩筆資料同時成功寫入、任一失敗則整筆回滾、共編邏輯正確、
      last_edited_by/at 正確更新、sort=latest 排序正確

4. 媒體編輯歷史（media_edit_history）
   → 驗證：每次 PUT 都正確寫入歷史紀錄

5. 心得系統（reviews，含 /reviews/latest）
   → 驗證：唯一性約束、owner-scoped、星級評分範圍檢查、最新列表排序正確

6. 愛心與通知（review_likes、notifications）
   → 驗證：不可對自己心得按讚、唯一性約束、按讚時正確產生通知、通知列表資料正確

7. 使用者公開主頁（users/:id）
   → 驗證：貢獻總覽數字與兩個分頁籤（心得、編輯紀錄）資料正確

8. 管理員下架功能（admin）
   → 驗證：僅 admin 可下架，其他人 403

9. 圖片上傳整合
   → 驗證：multer 正確處理檔案並儲存路徑

10. 容器化
    → 驗證：docker compose 完整啟動
```

每個模組的實作原則：對照階段一已寫好的測試，逐步讓測試由紅轉綠，不在測試之外新增規格外的行為。
